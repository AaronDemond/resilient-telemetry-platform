## Messages covered

- Envelope
- TelemetryEvent
- TelemetryMessage
- OperatorRequest
- RequestAcknowledgement
- StandardError

## Telemetry transport contract

`TelemetryMessage` is the transport unit for telemetry ingestion. Producers serialize one
`TelemetryMessage`, and consumers validate that both `envelope` and `event` are present
before processing either component. Because proto3 does not enforce required message
fields, component-presence and cross-component consistency checks remain application
responsibilities.

- `Envelope` carries transport identity and tracing metadata.
- `TelemetryEvent` carries the telemetry payload.
- `TelemetryMessage` guarantees that the two components are delivered in one serialized message.
- Existing `Envelope` and `TelemetryEvent` definitions and field numbers are unchanged, preserving generated APIs and wire compatibility for current consumers.
- `OperatorRequest` initiates an action.
- `RequestAcknowledgement` confirms the result.
- `StandardError` is a separate error payload, used when validation or operational processing fails.
